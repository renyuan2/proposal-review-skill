# 甲方视角的解决方案成果评测

读取用户提交的成稿及同批提供的调研、反馈、测算材料。以客户收到的版本为评测对象，保留源文件。使用成稿实际页序及项目确认的本期建设年度。建设年度以该项目提供的已确认材料为准。

1. 建立逐页索引。对本模板生成的 HTML，执行 `node scripts/prepare_html.mjs <成稿.html> <工作目录>`。对 PDF，执行 `python3 scripts/prepare_pdf.py <成稿.pdf> <工作目录>`。读取生成的 `pages.json` 中的逐页文本、截图和可用定位。打开关键页截图检查图表和版式。其他文档可按实际输出分页转换成 PDF，或按[报告数据格式](references/report-format.md)建立索引。保留源文档实际页序。扫描页可查看截图并据可见内容定位，逐字引述前核对识别结果。
2. 读[十一项标准、三类受众与整改分级](references/rubric.md)。默认用内置[《深化方案框架》16 页 HTML](references/深化方案框架.html)和[逐页编写说明](references/深化方案框架-逐页编写说明.md)，同事上传方案即可。项目明确采用其他模板时，用项目确认的版本。对照示例正文、版式和页底说明，按页面用途和所属模型匹配每一页，逐栏记录应写内容、实际写法和判断，包括通过页与补充页。根据模板列出应有的页面、栏目和必答内容，逐个模型反查实稿覆盖，标明整页、整栏或要点缺失。诊断页先查中栏放列，再用右侧事实验证。示例园区的系统、调研及概算是虚构的，用于对照写法。待评方案的事实、反馈和价格用本项目证据核实。报告的「评测依据」写明实际使用的模板。
3. 建立问题清单。合并同一根因，选一个主要类别并分级，保留相关检查项及原页位置。按熟悉业务的编写者来写：标题下判断，判断依据给页码和实填问题，影响写受阻的决定，改法用动作和验收依据收尾。模板要求、原文和细节放在逐页对照及证据定位里，缺页指向最该承接的现有页。另按三类甲方各自关注的事项检验成稿，每类收成一个关于方案取舍的主问题，用成稿页的代表性缺口举证。
4. 保存结构化评测结论，执行 `python3 scripts/render_report.py <pages.json> <review.json> <建议报告.html>`。报告在一个文件内包含原页及证据标记。修改清单逐条可勾选，生成给编写 Agent 的修改指令，包含问题、原稿位置和改法。指令要求通查同类问题，在对话里按编号给改动摘要及每个修改页的已验证直达链接。文件不支持按页跳转时，给修订稿链接和页码。勾选和复制在报告本地完成。
5. 验证报告可离线打开。确认问题和逐页模板检查能跳到正确页，筛选、翻页和窄屏可用，三个受众判断和十一项结论完整。抽查跨类别、跨优先级勾选、取消和复制生成的指令。用实际算式复算概算，交付 HTML 及简短结论并说明证据范围。

脚本所在目录以本 Skill 路径为准。HTML 捕获使用 Playwright 和 Chromium，可用环境变量 `PROPOSAL_PLAYWRIGHT` 指定 Playwright 的 `index.mjs`，用 `PROPOSAL_CHROME` 指定浏览器可执行文件。PDF 捕获使用 `pdfplumber` 及其 PDFium 渲染依赖。优先使用工作区提供的运行环境。报告渲染只需要 Python 标准库。
